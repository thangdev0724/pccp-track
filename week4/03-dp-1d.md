# Tuần 4 · Phần 3 — DP 1 chiều

> [⬅ Prefix Sum](02-prefix-sum.md) · Tiếp theo: [DP 2 chiều](04-dp-2d.md)

## Ý tưởng cốt lõi

- Trạng thái là **một chỉ số**: `dp[i]` = kết quả tối ưu (hoặc số cách) tính đến vị trí `i`
- Toàn bộ công việc nằm ở **công thức truy hồi**: `dp[i]` phụ thuộc `dp[i-1]`, `dp[i-2]`, hay mọi `dp[j]` với `j < i`? Câu trả lời quyết định độ phức tạp là `O(n)` hay `O(n²)`
- Khi `dp[i]` chỉ nhìn lại vài ô cố định, có thể bỏ mảng và giữ 2–3 biến → bộ nhớ `O(1)`

## Các dạng phổ biến

| Dạng | Cách làm | Bài toán tiêu biểu |
| --- | --- | --- |
| **Truy hồi cố định** | `dp[i]` từ `dp[i-1]`, `dp[i-2]` → `O(n)` | Climbing Stairs, House Robber |
| **DP trên đoạn kết thúc tại i** | `dp[i]` = kết quả tốt nhất của đoạn **kết thúc tại** `i`, đáp án là `max(dp)` | Maximum Subarray (Kadane) |
| **Nhìn lại mọi j < i** | `dp[i] = f(dp[j])` với mọi `j < i` → `O(n²)` | Longest Increasing Subsequence |
| **DP kiểu "đổi tiền"** | `dp[x]` từ `dp[x - coin]`, duyệt theo giá trị chứ không theo chỉ số | Coin Change |

Mẹo phân biệt hai kiểu định nghĩa hay bị lẫn:

- `dp[i]` = "kết quả tốt nhất **xét đến** `i`" → đáp án là `dp[n - 1]`, `dp` thường không giảm
- `dp[i]` = "kết quả tốt nhất của đoạn **kết thúc đúng tại** `i`" → đáp án là `Math.max(...dp)`, phải quét lại toàn mảng

## Ví dụ cơ bản — truy hồi cố định

Bài "không được chọn hai phần tử liền kề": ở mỗi vị trí chỉ có hai lựa chọn — lấy hoặc bỏ.

```js
const robLine = (nums) => {
  const n = nums.length;
  if (n === 0) return 0;
  if (n === 1) return nums[0];

  const dp = new Array(n).fill(0);
  dp[0] = nums[0];
  dp[1] = Math.max(nums[0], nums[1]);

  for (let i = 2; i < n; i++) {
    dp[i] = Math.max(dp[i - 1], dp[i - 2] + nums[i]); // bỏ i, hoặc lấy i + tốt nhất đến i-2
  }

  return dp[n - 1];
};
```

Bản rolling — cùng công thức, bộ nhớ `O(1)`:

```js
const robRolling = (nums) => {
  let skip = 0; // tốt nhất khi không lấy phần tử trước đó
  let take = 0; // tốt nhất khi đã tính cả phần tử trước đó

  for (const num of nums) {
    [skip, take] = [take, Math.max(take, skip + num)];
  }

  return take;
};
```

## Ví dụ mở rộng — DP trên đoạn kết thúc tại i, và DP kiểu đổi tiền

**Kadane** — `dp[i]` là tổng lớn nhất của đoạn con **kết thúc tại** `i`, nên đáp án phải lấy max toàn mảng:

```js
const maxEndingHere = (nums) => {
  let best = nums[0];  // KHÔNG khởi tạo 0: mảng toàn số âm sẽ ra sai
  let curr = nums[0];

  for (let i = 1; i < nums.length; i++) {
    curr = Math.max(nums[i], curr + nums[i]); // bắt đầu đoạn mới, hay nối vào đoạn cũ
    best = Math.max(best, curr);
  }

  return best;
};
```

**DP theo giá trị** — trạng thái là "số tiền", không phải "chỉ số":

```js
const minItemsToReach = (values, target) => {
  const dp = new Array(target + 1).fill(Infinity); // bài tìm MIN → khởi tạo Infinity
  dp[0] = 0;

  for (let x = 1; x <= target; x++) {
    for (const v of values) {
      if (v <= x && dp[x - v] !== Infinity) {
        dp[x] = Math.min(dp[x], dp[x - v] + 1);
      }
    }
  }

  return dp[target] === Infinity ? -1 : dp[target]; // không đạt được thì trả -1
};
```

**Nhìn lại mọi `j < i`** — khung `O(n²)` cho các bài kiểu dãy con:

```js
const longestChain = (nums) => {
  const dp = new Array(nums.length).fill(1); // mỗi phần tử tự nó là một dãy dài 1

  for (let i = 1; i < nums.length; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }

  return Math.max(...dp);
};
```

## Lỗi biên thường gặp

- Bài tìm **max** với dữ liệu có thể toàn số âm: khởi tạo `best = 0` là sai, phải là `nums[0]` hoặc `-Infinity`
- Bài tìm **min**: khởi tạo `Infinity` và nhớ kiểm tra `dp[x] === Infinity` ở cuối để trả về giá trị "không thể" theo đề (`-1`), đừng trả thẳng `Infinity`
- Nhầm hai kiểu định nghĩa `dp[i]`: định nghĩa "kết thúc tại `i`" mà lại trả về `dp[n - 1]` thay vì `Math.max(...dp)` → sai ở gần như mọi test
- Base case thiếu: mảng rỗng, `n === 1`, `target === 0`. Truy cập `dp[1]` khi mảng chỉ có 1 phần tử cho ra `undefined`, và `Math.max(undefined, ...)` ra `NaN` — sai **âm thầm**, không ném lỗi
- `Math.max(...dp)` với `dp` cỡ `10^5` trở lên có thể **tràn ngăn xếp** khi trải mảng. Với mảng lớn, dùng `dp.reduce((a, b) => Math.max(a, b), -Infinity)`
- Duyệt sai chiều: DP kiểu "mỗi món dùng **không giới hạn** lần" duyệt xuôi, "mỗi món dùng **tối đa 1 lần**" (0/1 knapsack rolling) phải duyệt **ngược**
- `new Array(n)` chưa `.fill()` cho ra mảng "rỗng" (sparse): `dp[0] = 1` rồi `dp[1] += dp[0]` sẽ ra `NaN`. Luôn `.fill(giá trị khởi tạo)`
- Đọc `dp[i - 2]` khi `i < 2` cho `dp[-1]` = `undefined` — luôn bắt đầu vòng lặp từ chỉ số an toàn và gán base case thủ công
