# Tuần 4 · Phần 4 — DP 2 chiều

> [⬅ DP 1 chiều](03-dp-1d.md) · [Mục lục tuần 4](README.md)

## Ý tưởng cốt lõi

- Trạng thái cần **hai** chỉ số: `dp[i][j]`. Hai nguồn gốc phổ biến là "hai chuỗi/hai dãy" (`i` là vị trí ở chuỗi A, `j` ở chuỗi B) và "lưới 2D" (`i`, `j` là toạ độ ô)
- Độ phức tạp mặc định là `O(m × n)` — bằng số ô của bảng, mỗi ô tính trong `O(1)`
- Rất nhiều bài 2D nén được về `O(n)` bộ nhớ vì mỗi hàng chỉ cần hàng ngay trước nó

## Các dạng phổ biến

| Dạng | Cách làm | Bài toán tiêu biểu |
| --- | --- | --- |
| **Đường đi trên lưới** | `dp[i][j]` từ ô trên và ô trái | Unique Paths, tổng đường đi nhỏ nhất |
| **Hai chuỗi** | ký tự bằng nhau → lấy `dp[i-1][j-1] + 1`; khác nhau → lấy max/min của hai ô kề | Longest Common Subsequence, Edit Distance |
| **0/1 Knapsack** | `dp[i][w]` = tốt nhất khi xét `i` món đầu với sức chứa `w` | Partition Equal Subset Sum |
| **Knapsack nén 1 chiều** | giữ một hàng, duyệt `w` **giảm dần** | cùng các bài trên, bộ nhớ `O(W)` |

## Ví dụ cơ bản — đường đi trên lưới

Mỗi ô chỉ đến được từ ô trên hoặc ô bên trái, nên số đường đi là tổng của hai ô đó:

```js
const gridPaths = (m, n) => {
  const dp = Array.from({ length: m }, () => new Array(n).fill(1)); // hàng 0 và cột 0 đều là 1

  for (let i = 1; i < m; i++) {
    for (let j = 1; j < n; j++) {
      dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
    }
  }

  return dp[m - 1][n - 1];
};
```

Đổi phép gộp thì đổi hẳn bài toán — tổng chi phí nhỏ nhất khi đi từ góc trên trái xuống góc dưới phải:

```js
const minPathSum = (grid) => {
  const m = grid.length;
  const n = grid[0].length;
  const dp = Array.from({ length: m }, () => new Array(n).fill(0));

  dp[0][0] = grid[0][0];
  for (let j = 1; j < n; j++) dp[0][j] = dp[0][j - 1] + grid[0][j]; // hàng đầu: chỉ đi ngang
  for (let i = 1; i < m; i++) dp[i][0] = dp[i - 1][0] + grid[i][0]; // cột đầu: chỉ đi dọc

  for (let i = 1; i < m; i++) {
    for (let j = 1; j < n; j++) {
      dp[i][j] = grid[i][j] + Math.min(dp[i - 1][j], dp[i][j - 1]);
    }
  }

  return dp[m - 1][n - 1];
};
```

## Ví dụ mở rộng — hai chuỗi & knapsack nén

Khung DP hai chuỗi. Bảng cỡ `(m + 1) × (n + 1)`, hàng/cột 0 nghĩa là "chuỗi rỗng":

```js
// Edit Distance: số phép chèn/xoá/thay tối thiểu để biến a thành b
const editDistance = (a, b) => {
  const m = a.length;
  const n = b.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = 0; i <= m; i++) dp[i][0] = i; // xoá hết i ký tự
  for (let j = 0; j <= n; j++) dp[0][j] = j; // chèn j ký tự

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (a[i - 1] === b[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1]; // ký tự khớp, không tốn thao tác nào
      } else {
        dp[i][j] = 1 + Math.min(
          dp[i - 1][j - 1], // thay
          dp[i - 1][j],     // xoá
          dp[i][j - 1],     // chèn
        );
      }
    }
  }

  return dp[m][n];
};
```

**0/1 knapsack** dạng "có đạt được tổng `target` không", nén xuống một chiều. Vòng trong duyệt **ngược** để mỗi món chỉ dùng một lần:

```js
const canReachSum = (nums, target) => {
  const dp = new Array(target + 1).fill(false);
  dp[0] = true; // tổng 0 luôn đạt được: không chọn gì cả

  for (const num of nums) {
    for (let s = target; s >= num; s--) { // NGƯỢC: dp[s - num] còn là giá trị của vòng trước
      dp[s] = dp[s] || dp[s - num];
    }
  }

  return dp[target];
};
```

Nếu duyệt xuôi, `dp[s - num]` đã bị cập nhật ngay trong vòng này → một món bị dùng nhiều lần, và bài toán biến thành "unbounded knapsack" — đúng công thức nhưng sai đề.

## Lỗi biên thường gặp

- `new Array(m).fill(new Array(n).fill(0))` tạo **m tham chiếu tới cùng một hàng**: sửa `dp[0][0]` thì cả bảng đổi theo. Luôn `Array.from({ length: m }, () => new Array(n).fill(0))`
- Lệch 1 giữa bảng và chuỗi: bảng cỡ `(m + 1) × (n + 1)` thì `dp[i][j]` ứng với **`i` ký tự đầu**, nên ký tự đang xét là `a[i - 1]` chứ không phải `a[i]`
- Quên khởi tạo hàng 0 / cột 0. Với bài đếm đường đi thì phải là `1`, với bài Edit Distance là `i` và `j`, với bài tính tổng là cộng dồn — mỗi bài một kiểu
- Knapsack nén 1 chiều: duyệt **xuôi** là lỗi kinh điển, biến 0/1 knapsack thành dùng lại vô hạn lần. Nhớ `for (let s = target; s >= num; s--)`
- `dp[i - 1][j - 1]` khi `i = 0` hoặc `j = 0` cho `undefined` — đó là lý do dùng bảng `(m + 1) × (n + 1)` thay vì `m × n`
- Đáp án nằm ở `dp[m][n]` (bảng `+1`) hay `dp[m - 1][n - 1]` (bảng đúng cỡ)? Lẫn hai cái này ra `undefined`, và `undefined` in ra vẫn "trông như" một kết quả
- Bảng `10^4 × 10^4` là `10^8` ô — quá bộ nhớ. Nếu ràng buộc lớn như vậy thì bài chắc chắn có cách nén hàng hoặc không phải DP 2D
- Bài "chia mảng thành hai phần tổng bằng nhau": tổng lẻ thì trả `false` ngay, đừng để DP chạy vô ích
